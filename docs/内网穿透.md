# frp 固定版本与节点安全部署说明

2026-10-29 核对官方仓库，固定使用 frp **v0.71.1**（2026-10-14发布，Apache-2.0）。官方资产记录在源码 `docs/windows-evidence/frp-official-release.json`；许可证原文为发行目录的 `FRP-LICENSE.txt`。Windows amd64 ZIP 的 SHA256 为 `b90074b2b6a1d792a7a40f085ac6d276bcab2d1bc60201f8a86ca53ce65ce821`，解压的 frpc.exe 为 `23d11640bee87207c7a99d006b84c554df997feeba7ac7243db20a88a9cb5e01`，下载和每次启动均校验。不自动使用公共免费节点、不自动接受第三方配置、不通过Shell拼接命令或安装系统服务。

## 在开服工坊里操作

没有公网中转节点时，可以先准备组件和阅读说明；本软件不提供免费共享节点，也不自动租用 VPS。本轮真实验证只在 127.0.0.1 进行，不表示已经有公网入口。

1. 准备自己的公网 VPS 或可信服务商提供的兼容 frps 节点。向节点管理员取得：地址、控制端口、分配的游戏端口、证书名称、单张 PEM 格式 CA 公钥证书、32–128 位安全字符 Token。
2. 打开“联机指引”，选择游戏实例，切到“frp 内网穿透”，点击“准备 frp 组件”。官方包约14MB，组件安装在当前 Data 内；不安装系统服务。
3. 点击“穿透配置”。本机目标固定为所选实例的 `127.0.0.1:游戏端口`。tModLoader 本机端口为7777，朋友端口由节点分配；示例也用7777，不能与中转控制端口相同。
4. 填写节点信息，选择保存在本地磁盘、只含单张 CA 公钥证书的 PEM 文件，核对界面 SHA256 指纹。不能使用 CA 私钥、PFX、PKCS7、证书合集或网络路径。
5. 首次填写 Token；留空仅表示保留已有的本机加密凭据。点击保存不会启动穿透。
6. 先启动游戏并确认服务端就绪，再点击“启动穿透”。页面只有收到指定代理的成功注册日志后才显示注册完成；失败、断线或证书不匹配会清除可复制地址。
7. 朋友用匹配版本的游戏客户端连接“配置的中转地址”和游戏端口。必须从异地实际加入，才完成公网验收。停止穿透只关闭 frpc；停止游戏或退出管理器会关闭对应转发。

| 配置项 | 自建节点示例 |
|---|---|
| 中转节点地址 | 节点的公网 IP 或域名 |
| 中转控制端口 | 7000 |
| 朋友连接的端口 | 7777，需由节点 allowPorts 允许 |
| 证书中的节点名称 | 与服务器证书 SAN 匹配的名称或 IP |
| CA 证书 | 本地 `ca.crt`，仅单张公开 CA 证书 |
| Token | 同节点一致，建议生成64位随机十六进制值 |

证书名称用于 TLS 身份校验，可以与连接地址不同。例如连接公网 IP，但验证证书中的固定域名；无需让游戏客户端安装此 CA，也不修改 Windows 系统根证书库。凭据文件被改动、跨用户复制或目录迁移后可能被拒绝；此时备份并移走对应 `Data/Tunnels/Profiles/实例ID/tunnel.json`，在界面重新填写可信节点、CA 和 Token，不要关闭证书校验。

## 两端各做什么

本地开服电脑运行 frpc，主动连接一台用户自己控制或信任的公网节点frps；朋友连接节点公网地址与远端TCP7777。frp不会给本地电脑凭空分配公网IP。中转节点可观察经过它的游戏流量；TLS保护frpc到frps的链路，不把普通游戏客户端到节点的连接自动变成端到端加密。公开前可在游戏配置设置密码；不要把路由器管理、Windows远程桌面或其他本地端口一同转发。

下方 frps 配置只开控制TCP7000，且只允许远端TCP7777，每客户端最多一个端口；不设置仪表盘、HTTP虚拟主机、KCP/QUIC或SSH网关。本地 frpc 配置由管理器生成，仅转发所选实例的本机 TCP 端口。所有示例域名与文件路径均需替换，不能以示例域名当作已经部署的节点。

## 公网 IPv4 与 IPv6 常见问题

**软件放在有公网 IP 的服务器上，会自动配置吗？** 当前版本只读取本机 IPv4 和本机端口监听，没有实现公网 IP 自动识别，也不会自动修改 Windows 防火墙、路由器、云安全组或部署 frps。云服务器的公网 IPv4 可能由平台映射，读网卡不一定能取得；查到出口公网地址也不等于允许外部连接。

如果管理器和游戏都运行在有公网 IPv4 的 Windows 服务器上，通常直接让朋友连接“服务器公网 IPv4 + 游戏端口”即可，不必使用 frp。仍须让游戏监听可访问的本机接口，并在 Windows 防火墙和云平台安全组放行对应端口，例如 tModLoader 的 TCP7777。不要把云平台映射的公网地址强行填成不存在的本机绑定地址。如果游戏仍在家中，公网服务器只作为中转，则仍需在公网服务器运行 frps，家中管理器运行 frpc；仅把管理器复制到公网服务器不会转发家中的游戏。

**IPv6 也要申请吗？** 家庭宽带若已提供 IPv6，通常由运营商分配前缀、光猫/路由器分配到电脑，不需要为每台电脑单独申请地址。需在路由器按运营商方式启用 IPv6 与前缀授权，再让终端自动获取；如果始终没有可用地址，应先向运营商确认线路支持情况。[TP-LINK 配置说明](https://smb.tp-link.com.cn/service/articleDetail.html?id=4370)

云服务器按服务商规则启用和分配 IPv6，可能还要单独开通公网带宽或调整路由。以阿里云 IPv6 网关为例，默认取得地址只具备私网通信能力，须开通公网带宽后才能与 IPv6 互联网通信；因此“看到 IPv6 地址”本身不能证明可公网联机。[阿里云说明](https://help.aliyun.com/zh/ipv6-gateway/product-overview/what-is-an-ipv6-gateway)

**IPv6 联机怎么操作？**

1. 确认开服电脑获得可公网路由的 IPv6，并且存在可用的 IPv6 上网线路。`fe80::` 开头为链路本地地址；`fc`/`fd` 开头的唯一本地地址也不能用作互联网直连地址。需要使用开服电脑的地址，不能把路由器 WAN 地址当成电脑地址。[Microsoft 地址说明](https://learn.microsoft.com/en-us/windows/win32/winsock/link-local-and-site-local-addresses-2)、[RFC 4193](https://datatracker.ietf.org/doc/html/rfc4193)
2. 确认游戏服务端监听 IPv6，且玩家客户端和玩家所用网络能使用 IPv6。仅 IPv4 的玩家不能直接连接 IPv6 地址。
3. 在电脑防火墙、路由器 IPv6 防火墙及云安全组按需允许游戏端口入站。普通家庭 IPv6 直连通常不用 IPv4 式 NAT 端口映射，但仍受防火墙和运营商策略约束。
4. 向朋友提供 IPv6 和端口。支持将地址与端口写在同一栏的客户端通常使用 `[IPv6地址]:端口`；分栏填写的客户端按其说明输入，不能假设所有游戏都接受同一格式。地址可能变化，长期使用应选择合适的稳定地址或配置域名 AAAA/DDNS。
5. 从另一条具有 IPv6 的网络实际加入并确认游戏状态，才能判定联机成功；本机监听或 IPv6 网页访问成功不能代替入站游戏测试。

当前 tModLoader v2026.08.3.0 只完成 IPv4 实测，尚未完成 IPv6 玩家加入验证。该版本客户端的地址解析会将末尾冒号后的数字尝试作为端口，不能承诺直接粘贴裸 IPv6 就能使用。必要时可另行配置 IPv6/IPv4 TCP 桥接；Windows `portproxy v6tov4` 仅支持 TCP，并不解决没有 IPv6 线路或防火墙未放行的问题。本软件目前不自动创建此类系统规则。[tModLoader 对应版本源码](https://raw.githubusercontent.com/tModLoader/tModLoader/v2026.08.3.0/patches/tModLoader/Terraria/Netplay.cs.patch)、[Microsoft portproxy 说明](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/netsh-interface)

## 证书不能只开TLS开关

官方 v0.71.1 `pkg/transport/tls.go` 的 `NewClientTLSConfig` 在 **未配置 trustedCaFile 时会设置 InsecureSkipVerify=true**。因此客户端必须导入受信节点的CA证书，并设置与服务器证书SAN匹配的 `transport.tls.serverName`；本集成不提供跳过证书验证的选项。仅持有token不代替服务端身份校验。节点应配置自己的server.crt/server.key，不能依赖默认随机自签证书。

以下是可信管理员电脑上生成私有CA和节点证书的OpenSSL示例；域名需改成自己的节点身份。CA私钥加密保存，不上传到公网节点；节点只得到它自己的server.crt/server.key。开服电脑只需要ca.crt。所有文件均不导入Windows系统根证书库。

```sh
umask 077
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -aes-256-cbc -out ca.key
openssl req -x509 -new -sha256 -days 365 -key ca.key -out ca.crt -subj "/CN=Kaifu-frp-Root-CA" -addext "basicConstraints=critical,CA:TRUE" -addext "keyUsage=critical,keyCertSign,cRLSign"
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -out server.key
openssl req -new -sha256 -key server.key -out server.csr -subj "/CN=relay.example.com"
cat > server.ext <<'EOF'
basicConstraints=critical,CA:FALSE
keyUsage=critical,digitalSignature,keyEncipherment
extendedKeyUsage=serverAuth
subjectAltName=DNS:relay.example.com
EOF
openssl x509 -req -sha256 -days 90 -in server.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out server.crt -extfile server.ext
openssl verify -CAfile ca.crt -verify_hostname relay.example.com server.crt
openssl rand -hex 32
```

最后一条命令生成64位十六进制随机token（256bit原始随机量）。将同一token分别填入管理器和节点环境变量 `SWB_FRP_TOKEN`，不要写入示例文件、聊天记录或共享截图。到期前更新证书；不得为绕过过期而关闭校验。

## 中转节点配置

保存为节点上的 `/etc/frp/frps.toml`：

```toml
# Replace paths and provision SWB_FRP_TOKEN in the server process environment.
# Client token must contain only A-Z, a-z, 0-9, _ and - (32-128 characters).
bindAddr = "0.0.0.0"
bindPort = 7000
proxyBindAddr = "0.0.0.0"
transport.tls.force = true
transport.tls.certFile = "/etc/frp/server.crt"
transport.tls.keyFile = "/etc/frp/server.key"
auth.method = "token"
auth.token = "{{ .Envs.SWB_FRP_TOKEN }}"
auth.additionalScopes = ["HeartBeats", "NewWorkConns"]
allowPorts = [{ single = 7777 }]
maxPortsPerClient = 1
detailedErrorsToClient = false
log.to = "console"
log.level = "info"
log.disablePrintColor = true
# No webServer.port, HTTP/HTTPS vhost, KCP/QUIC listener or SSH gateway is enabled.
```

服务器端不要添加 `transport.tls.trustedCaFile`；该项会要求客户端证书，属于另一种双向 TLS 部署模式。这里使用服务端证书校验与 Token 认证。

## 节点运行

在有公网IP的Linux节点使用相同固定版本frps；核对该平台官方摘要。将frps、最小配置、server.crt、server.key放到只允许管理员/专用服务账号写入的目录。用不具备管理员权限的专用账号运行；7000与7777都不需要特权端口权限。私钥和token环境文件仅允许节点管理员/服务账号读取，目录及二进制不可由其他用户写入。只按需放行这两个TCP端口，不开放管理仪表盘。

```sh
# token由服务环境或权限受限的EnvironmentFile提供，不作为命令行参数。
./frps verify -c /etc/frp/frps.toml
./frps -c /etc/frp/frps.toml
```

Windows端由管理器生成受限配置，再使用固定版本 frpc 严格解析并启动；本机游戏服务应先就绪。frpc的 `loginFailExit=true` 让最初的证书、token或连接失败明确退出。页面显示“代理已注册”只对应frps接受代理；真正公网成功必须由异地客户端连接或端到端有效载荷探针证明。停止穿透只停止frpc，不终止游戏进程。

## token与日志边界

frp的Go环境变量模板是**原样替换**，没有TOML字符串自动转义。因此 `auth.token = "{{ .Envs.SWB_FRP_TOKEN }}"` 必须配合严格字符约束：整个值匹配 `\A[A-Za-z0-9_-]{32,128}\z`，不允许空白、引号、反斜杠、换行或模板括号。建议管理器直接生成64位十六进制值；不要使用简单重复口令。

本地持久化使用当前Windows用户范围DPAPI，配置只保留环境变量引用，不把明文token写入TOML、JSON、日志或命令行。运行时只传给frpc子进程环境；同用户/管理员仍可能检查进程环境，不能将DPAPI描述成对本机管理员保密。不要继承token给游戏进程。

日志保持info，禁用彩色输出，不开启配置/环境debug转储。输出及异常在进入日志队列、磁盘和界面前替换当前会话已知 Token 的精确值。配置验证错误也走同样的脱敏，不把完整ProcessStartInfo/环境序列化到报告。保持日志长度上限。

## 兼容性与已知安全修复

管理器仍保留net48/netstandard2.0与Win7 SP1/8.1/10/11 x64目标；**本次frp组件单独要求Win10或更高**。Go官方最低要求指出Go1.21及以后需要Windows10或Windows Server2016；frp0.71.1构建要求Go1.26.0+。旧系统显示组件不可用，不悄悄下载停止维护的老版。

官方已有两项公开安全公告，v0.71.1在修复版本之后；不要将开源或本轮测试描述为绝对安全：HTTP `routeByHTTPUser`认证绕过已在0.68.1修复，SSH网关拒绝服务已在0.70.1修复。本集成都不启用这两个功能。仍需跟踪后续版本及安全公告。

## 本机测试如何复现

需要支持 .NET SDK10 的 Windows10/11 x64。先从上述官方发布下载并校验 ZIP，解压取得 frps.exe；不要替换摘要校验，不导入测试 CA 到系统信任库。

```powershell
dotnet run --project tools/frp-test-certificates/Certificates.csproj -c Release -- C:\Temp\swb-frp-certs
dotnet build tools/frp-tests/FrpTests.csproj -c Release
& .\tools\frp-tests\bin\Release\net48\ServerWorkbench.FrpTests.exe C:\Temp\frp_0.71.1_windows_amd64.zip C:\Temp\frp_0.71.1_windows_amd64\frps.exe C:\Temp\swb-frp-certs C:\Temp\swb-frp-test-new
```

证书目录与测试数据目录必须新建且为空；测试私钥仅供回环自检，不能用于真实节点。测试 EXE 必须在已加载用户配置的 Windows 账户下运行，否则 DPAPI 会拒绝保存，不会降级为明文。测试目标是随机回环端口上的模拟 TCP 服务，不操作现有游戏世界。覆盖真实 TLS 下128KB随机二进制数据、错误 Token/CA/证书名称、配置和 CA 篡改、私钥容器/多CA/UNC拒绝、启动取消、停游戏断开、节点丢失、进程退出清理及凭据落盘扫描。


## Linux 中转一条指令部署

已提供配套的 [ServerWorkbench Relay](https://github.com/Cymene0n0/serverworkbench-relay)：在有公网 IPv4 的 Ubuntu 22.04+ / Debian 12+ systemd 主机上安装固定 frps、生成 TLS 身份和 Token。按该项目说明导出 CA，并在本软件中填写节点信息。Linux 仅负责中转，游戏与世界仍在自己的 Windows 电脑运行。实际公网玩家加入仍需另行验证。
